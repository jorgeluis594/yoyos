# WhatsApp message normalization

`Normalize` accepts the unwrapped `events.Message` produced by live receipt or `Client.ParseWebMessage` and checks its raw wrappers so historical edit events are excluded. It returns one public message, an explicit unresolved chat identity, or an excluded result. A supported message with an invalid timestamp or identity returns an error. The caller retains the source event and protocol recovery data until durable admission completes; this package performs no storage, network access, downloads, or age filtering.

Pass the originating account JID as `own`. `ownAlt`, `MessageInfo.SenderAlt`, and `MessageInfo.RecipientAlt` may be used only when they are verified protocol alternatives for the same address. `VerifiedLIDs` must contain verified non-device PN-to-LID mappings from the account's protocol store. The normalizer never derives a LID from a PN or username. A missing chat LID returns `UnresolvedIdentity` without a public ID for WA-07 to preserve and resolve. A missing own LID is an error because there is no safe account under which to admit a pending message.

`MessageID` encodes the exact three-string tuple as `wa-message:v1:` plus raw Base64url of compact JSON. `NewDeliveryID` uses cryptographic randomness by default and asks the caller's pending lookup before returning an ID. Admission must serialize that lookup with insertion. Replay reads and preserves the stored delivery ID; it does not call `NewDeliveryID` again.

Image references are `wa-image:v1:` plus raw Base64url JSON, with optional metadata. Omitted metadata is valid; malformed present fields are rejected. They contain an attachment media key when WhatsApp supplies it; callers must treat the descriptor as sensitive and avoid logging it. `ValidateImageReference` checks the descriptor before a future explicit download. It does not download or decrypt media.
