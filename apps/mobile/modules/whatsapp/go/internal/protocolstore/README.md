# WA03 Go protocol store preparation

This package implements the pinned whatsmeow `AllStores` and `DeviceContainer` interfaces over the approved `protocolstate` v1 codec. It is internal and has no production caller yet. `Open` requires an active generation ID, canonical account LID, a synchronous native `Storage`, the trusted read recovery bound, and the current new-content recovery bound. It reads a coherent native revision before exposing a store. The callback API is exactly `ReadState(string) (string, error)` and `ApplyChanges(string) (string, error)`; it does not change the WA01 public probe binding.

`ReadState` sends `{"contractVersion":1}` and accepts only a v1 `success/data` or `failure/error` result. Successful `data` has `revision`, `sessionRevision`, `session`, and `pending`. `session` is null or `{accountId,protocolSchemaVersion:1,records}`. Pending records have native-assigned `createdRevision` and `createdOrdinal` plus the fields in `PendingInsert`. `ApplyChanges` sends `contractVersion`, `generationId`, `accountId`, `expectedSessionRevision`, ordered `protocolChanges`, `pendingInserts`, and `pendingIdentityUpdates`; a successful response supplies the new `revision` and `sessionRevision`. Each change is a codec-validated `put` or `delete`. The native writer must independently validate the complete request, active registered generation/account, revision, record budget, pending collision/identity rules, and final encrypted session size before atomic durable publication. Go's payload cap is `16 MiB + recovery bound + 12,340 bytes`, where codec value and pending binary Base64 expansion are already included; this is a binding cap, not final encrypted admission. The read bound may exceed the current new-content bound after options shrink.

Outside `DoDecryptionTxn`, every write waits for `ApplyChanges`. Inside it, reads see staged writes; ordered changes and prepared pending inserts/identity updates publish in one callback. Native confirmation can change the global revision while the session revision stays fixed. An invocation error, panic, malformed reply, or incoherent revision stops the generation and triggers readback; the store never resends the mutation. `ReadbackError` exposes readback failure. Native structured errors retain their codes; stale generation/revision and storage/state errors also read back. A stopped store cannot write again. A transaction panic or failure after staging changes stops the store so altered Signal memory is not reused.

`PreparePendingInsert` copies the supplied recovery metadata and Base64 plaintext descriptors into the staged request. The future receive adapter must provide the versioned `messageInfoJson` DTO and fully normalized message; this package currently verifies JSON shape, Base64, hashes, and source/format consistency, not that future DTO schema. `PreparePendingIdentityUpdate` is an explicit update, never a pending replacement. `PutBufferedEvent`, `GetBufferedEvent`, `ClearBufferedEventPlaintext`, and `DeleteOldBufferedHashes` return `RECOVERY_CONTEXT_MISSING` until the receive hook supplies and consumes that context with pending-aware retry-marker handling. Thus stock inbound receive is deliberately blocked in this preparatory package. `retry-hash` remains metadata-only. `DeleteDevice` returns `NATIVE_LOGOUT_REQUIRED`; the native controller owns logout. `PutDevice` durably saves linked credentials and attaches all stores only after commit; `RestoreDevice` reconstructs them and checks the account LID. Native controller authorization for creation of a fresh session/key remains required. Keep whatsmeow `UseRetryMessageStore=false` in the receive-only controller. Every outgoing EventBuffer method returns `OUTGOING_UNSUPPORTED` if accessed.

The controlled `Storage` test double checks Go's callback shapes, staging, durability wait, concurrency, readback, and failure behavior. It cannot prove Kotlin/Swift writer validation, encryption, atomic disk publication, real ACK suppression, native generation registration, or final session admission. WA02 writer review and the full WA03 receive/controller integration remain acceptance gates.
