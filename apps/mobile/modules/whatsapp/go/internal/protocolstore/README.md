# WA03 transactional protocol store

`Open` reads a coherent native revision and exposes the pinned whatsmeow `AllStores` and `DeviceContainer` interfaces. The v1 restore callbacks are `ReadState(string) (string, error)` and `ApplyChanges(string) (string, error)`. The native writer validates registered generation and account, expected session revision, ordered record changes, pending inserts and identity updates, capacity, and the final encrypted session before durable publication. Go does not replace pending, acknowledge a delivery, or log out through these callbacks.

`NewFirstLinkDevice` creates pairing keys in memory. After whatsmeow verifies the paired JID and LID, its container calls `BeginFreshSession(string) (string, error)` with the complete device record. Native publishes that record and the encrypted session in one commit using its provisional key lifecycle. A lost reply retries only the identical record; a different established device is rejected. The first-link container latches a typed `StopReason()` if publication fails. The native controller registers a fresh generation before pairing and retires it on stop.

Outside `DoDecryptionTxn`, writes wait for native commit. Inside it, reads see staged writes. `CaptureReceive` clones v2/v3 encrypted children and metadata before decryption. `PutBufferedEvent` stages critical post-decryption protocol writes through `RecoveryProcessor`, then stages normalized or pending-LID content and metadata-only retry hash with Signal changes. A failed stage publishes none. Every committed WA03 pending row is therefore protocol-ready and a resolved row may be delivered from native recovery state without a live account, session, or Go client. WA03 has no legacy pending format or replay migration.

`GetBufferedEvent` rereads current native pending to distinguish unconfirmed content from a completed retry marker. The patched receive path withholds transport ACK for a pending duplicate and allows a completed duplicate after native confirmation. `ClearBufferedEventPlaintext` verifies the durable marker while retaining the only plaintext copy in native pending. Cleanup rereads current pending and protects referenced hashes. Outgoing EventBuffer methods return `OUTGOING_UNSUPPORTED`; `DeleteDevice` returns `NATIVE_LOGOUT_REQUIRED` because the native controller owns logout. UseRetryMessageStore remains false for the receive-only controller.

The nonnative test script copies the pinned whatsmeow source into a temporary directory, applies the versioned patch, and runs Go race, vet, and controlled transport tests. These checks do not prove Kotlin/Swift execution, encryption durability, or live WhatsApp behavior; native execution was waived for this task.
